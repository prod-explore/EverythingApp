# 0010 — Text-file tools without approval, and connectors added by URL

**Status:** accepted

**Context.** The agent changed files only through `run_bash` (`cat <<EOF`, `sed -i`), so every edit went through the command policy and asked for approval — the opposite of how Claude Code behaves, where editing a text file is the everyday action and only commands and network access are gated. The Files editor refused anything above ~96 KB (a base64 payload in a single `bash -c` argument hit the kernel's 128 KiB argument limit). Connectors could be added from Settings, but through a minimal form (name by hand, no test, no tool list, no edit), and one that was down at startup stopped the whole orchestrator.

**Decision.**
- **`read_file`, `edit_file`, `write_file`** are built-in chat functions (virtual tools, `file-tools.ts`) for chats with a sandbox. They reach only `/workspace` of the chat's own sandbox, never `.git`, and refuse binary content. They need **no approval**: a checkpoint of the workspace is taken at the start of every turn (Files → Checkpoints rolls back), and every change is written to the audit log (`agent_file_edit`, path and size only). `edit_file` replaces an exact, unique piece of text (or all occurrences on request) and returns a short before/after; `write_file` replaces a whole file. In plan mode only `read_file` runs. Shell commands still go through the command policy.
- **One write path** (`workspace-write.ts`) serves the agent and the Files editor: the content is staged next to the target in base64 chunks of at most 40 KB and moved into place with one `mv`, keeping the file's mode — an interrupted write never leaves a half-written file, and 512 KB files work.
- **The Files preview is read-only**; a pencil button switches to the editor. Saving takes a checkpoint first and needs no approval.
- **Connectors** are one list (Settings → Connectors): the operator's (`MCP_CONNECTORS`, shown as *built-in*, reconnect only) and those added by URL. Adding takes a URL and an optional token; the name comes from the address unless given. *Test* connects, lists the tools and disconnects without saving. A connector can be edited (URL, token), reconnected, disabled and removed. Tokens are encrypted in the key vault. Plain `http://` is accepted only for local and private addresses; credentials in the URL are refused.
- **Trust:** tools of a connector added in Settings always ask for approval until the user grants them from the approval card ("always"). The by-name auto-approve list (`AUTO_APPROVE_TOOLS`) applies to operator-configured connectors only, so a server cannot get a free pass by naming a tool `get_path`.
- **Failure isolation:** a connector that is down at startup is shown as disconnected (with the reason) instead of stopping the server; the registry loads each connection separately. A call that fails because the server lost the session (restart, expiry, connection refused) reconnects and repeats once — never after a timeout or a cut mid-call, since the call may have run.

**Also changed (from the audit in the vault).** The command policy now reads `$'…'` quoting correctly, treats text nested too deeply to analyse as "ask" instead of letting it through, and checks the always-blocked list against the command with quotes and the binary path removed; the key vault derives each stored key once instead of running scrypt on every read; secrets in logged tool arguments are redacted; a client resetting the live-view WebSocket before the handshake no longer raises an uncaught error.

**Consequences.** Editing files feels like Claude Code and costs no clicks; the safety net is the checkpoint, not a prompt. A connector added by hand asks once per tool. Not built: diff-review of agent edits before they land (the checkpoint and the shown diff replace it).
